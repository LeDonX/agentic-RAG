 🗓️  Day 02 — 基础语法（2026-10-12）
════════════════════════════════════════════════════════════════════
 📦 产出物：learning/day02_calculator.py（4 组用例通过）

 ── 💡 一、知识点速记 ─────────────────────────────────────────────
  · 动态类型：变量没有类型，类型挂在对象上
        对比 Java：int a=1 变量本身是 int 容器；Python a=1 只是把名字绑到 int 对象，之后可重绑 str
  · f-string：f"{aa/cc:.2f}" 直接内嵌表达式 + 格式说明符
        对比 Java：≈ String.format("%.2f", v)，但更短且能内嵌任意表达式
  · None：唯一空值，用 is None 判断，不用 == None
        对比 Java：≈ null，但 None 是真实对象（类型 NoneType）
  · 输入输出：input() 永远返回 str，参与计算前必须 float()/int() 转换
        对比 Java：≈ Scanner.nextLine() 返回 String，同样要 Integer.parseInt
  · 真除 vs 整除：/ 永远返回 float，// 才是整除
        对比 Java：Java 两个 int 用 / 就是整除  ← 最易踩的惯性坑

 ── ❌ 二、错题 / 踩坑 ─────────────────────────────────────────────
 【M-02-1】/ 与 // 混淆   #语法
   现象：7 / 2 期望 3，实际得 3.5
   错误写法：result = 7 / 2
   根因：把 Java「两个 int 相除即整除」的心智模型搬到了 Python
   正解：7 // 2 == 3（整除）；7 / 2 == 3.5（真除）
   Java 对照：Java 7/2==3（int 截断）、7.0/2==3.5；Python 的 / 与操作数类型无关，永远真除
   复发：—（已复述通过）

 🗓️  Day 03 — 容器（2026-10-13）
════════════════════════════════════════════════════════════════════
 📦 产出物：learning/day03_containers.py（已完成：TODO 1–10 全部跑通；Day 3 验收通过）
 📌 状态：Block A（list/tuple/for）、Block B（dict/set）、Block C（推导式/切片/解包）全部完成；
        当日验收通过（3 题，Q3 经纠正后掌握）

 ── 💡 一、知识点速记 ─────────────────────────────────────────────
 ◆ Block A — list / tuple / for
  · list：有序、可变、可重复、可混装任意类型（无需泛型）
        负索引 nums[-1] = 最后一个；切片 nums[1:3] 含头不含尾（Java 要 subList）
        对比 Java：list ≈ ArrayList<Object>，但 Python 没有「定长数组」概念
  · tuple：不可变序列；(5,) 才是单元素元组，(5) 只是数字
        可哈希规则：list 可变→不可哈希→不能当 dict key；tuple 不可变→可哈希→可以
        对比 Java：无直接对应，最近似 List.of() / 匿名 record
  · 解包：x, y = point；return a, b 本质返回一个 tuple（Python 天然多返回值）
  · for 心智模型：for item in iterable ≈ Java for-each（迭代机制相同），差异两点
        1) Python 没有 C 风格 for(i=0;i<n;i++)，要下标用 range(n)
        2) 循环变量循环结束后仍然存活；Java 循环变量出作用域即失效
        for name, score in students: 遍历「元组列表」时直接解包
  · 执行模型：Python 先整篇编译再执行 → 语法错误会挡住后面的运行期错误，只报第一个错

 ◆ Block B — dict / set
  · dict：d[k] 取不到抛 KeyError；d.get(k, default) 才安全；"k" in d 判 key；保持插入顺序
        对比 Java：≈ HashMap，但 Java get 取不到返回 null（不报错）  ← 最大惯性坑
        dict(二元组列表) 可直接转换；for k, v in d.items() 遍历（≈ entrySet()）
        key 必须可哈希：str/int/tuple 可以，list 不行
  · set：自动去重、元素必须可哈希；| & - 有独立运算符（Java 只能调 addAll/retainAll/removeAll）
        ⚠ {} 是「空 dict」，空集合必须写 set()
        set 无序：顺序由哈希决定、跨进程还会变（CPython 对 str 默认哈希随机化）
        → 要顺序别用 set，用 list / dict

 ◆ Block C — 切片 / 推导式 / 解包
  · 切片 seq[start:stop:step]：含头不含尾；s[::-1] 反转、s[::2] 隔一个取
        对比 Java：Java 无切片语法，最接近 subList；
        但 subList 是视图（改它会改原 list），Python 切片是新对象（拷贝）  ← 关键差异
  · 推导式：[表达式 for x in 可迭代 if 条件]；字典 {k: v for ...}；集合 {x for ...}
        对比 Java：≈ Stream 的 filter/map/collect，但 Python 一行搞定
        列表推导式立即求值；要惰性用生成器表达式 (x for ...)
  · 解包：first, *rest = seq（* 把剩余收成一个 list）；a, b = b, a 交换无需临时变量
        对比 Java：无多重赋值/星号解包，交换必须用 temp

 ── ❌ 二、错题 / 踩坑 ─────────────────────────────────────────────
 【M-03-1】格式说明符不能脱离 f-string 使用   #语法
   现象：print(total/len(students):.2f) → SyntaxError: invalid decimal literal
   错误写法：print(total/len(students):.2f)
   根因：.2f 是 f-string 内部的格式说明符，只能写在 {} 冒号之后，不是独立表达式语法
   正解：print(f"{total/len(students):.2f}")
   Java 对照：≈ System.out.printf("%.2f%n", avg)；Java 格式串与参数是分开两部分，
        Python 是「表达式 + 格式说明符」一起塞进 {}
   复发：—

 【M-03-2】累加变量未初始化   #语法
   现象：NameError: name 'total' is not defined
   错误写法：循环里直接 total += score，循环前没有 total = 0
   根因：+= 会先读取 total 再赋值；Python 没有「声明即可用」，读未赋值的名字就报 NameError
   正解：循环前先 total = 0
   Java 对照：Java 编译期就报「可能未初始化」；Python 运行期才报，异常类型是 NameError
   复发：—

 【M-03-3】把 f-string 当类型转换用   #语义 #易复发
   现象：total += f"{score}" → TypeError: unsupported operand type(s) for +=: 'int' and 'str'
   根因：f-string 是「排版出字符串」，不是类型转换；f"{88}" 得到 "88"(str)，int+str 直接报错
   正解：total += score；真要转类型用 int() / float() / str()
   Java 对照：Java s + 88 会隐式转字符串；Python 不做隐式转换，int+str 一律 TypeError
   复发：—

 【M-03-4】括号不配对   #语法
   现象：print(score_map.get("赵七", 0))) → SyntaxError: unmatched ')'
   错误写法：多打一个右括号
   根因：print( 一层、get( 一层，只需 2 个 )；第 3 个无处配对
   正解：print(score_map.get("赵七", 0))
   Java 对照：语法错误同样编译期报错；要点是「括号/引号必须成对」，
        且 SyntaxError 会挡住整文件执行（呼应 M-03-1）
   复发：—

 【M-03-5】变量名拼写错误   #语法
   现象：print(sccres[::-1]) → NameError: name 'sccres' is not defined. Did you mean: 'score'?
        前面已打印的正常输出保留，跑到那行才崩
   根因：Python 没有「声明」，名字必须先赋值存在；拼错的名字从未绑定 → NameError
   正解：print(scores[::-1])
   Java 对照：Java 拼错是编译期错误、整份不编译；Python 运行期才报，前面输出保留
        → SyntaxError（全不跑）vs NameError（跑到那行才崩）的分水岭
   复发：—

 【M-03-6】误解「list 不能当 key」的原因   #概念
   现象（验收 Q3 答错）：答成「list 可变→可能重复→违反 set 去重」，把「哈希」与「去重」混为一谈
   根因：真正原因是 list 不可哈希（unhashable），与「是否会重复」无关；
        Python 对可变容器故意不提供 __hash__  →  hash([1,2]) 报 TypeError
        为什么可变就不能哈希：当 key 后内容一变 → 哈希也变 → 找不回该 key，哈希结构损坏
   正解：用 tuple（不可变→可哈希）：d[("张三", 88)] 合法；可变容器一律不行
   Java 对照：Java 不禁止可变对象当 key（编译期不管），只有运行时 hashCode 变了才 get 不到；
        Python 在语言层面直接把可变容器设为不可哈希
   复述（2026-10-13，已掌握）：答「list 可变 → 不可哈希；tuple 不可变 → 可哈希」✅
   复发：—

 🗓️  Day 04 — 控制流与函数（2026-10-14）
════════════════════════════════════════════════════════════════════
 📦 产出物：learning/day04_functions.py、learning/day04_demo.py（导师示范）
 ✅ 状态：Block A 控制流 5 点 + Block B 函数 5 点（⑥⑦⑧⑨⑩）全部完成；Day 4 验收通过

 ── 💡 一、知识点速记 ─────────────────────────────────────────────
 ◆ Block A — 控制流（5 点）
  · if / elif / else：条件不加括号，行尾 : + 缩进分层；elif 是一个词（不是 else if）
        对比 Java：Java 要 if (a > b) { }；Python 靠「冒号 + 缩进」，多分支链用 elif
        命中第一个真分支后其余分支全部跳过（更易漏判边界：>= 90 在前、>= 60 在后）
  · 真值判断 truthiness（验收考点）：一句话记法「空 / 零 / 无」为假
        数值看「是否为 0」（0、0.0 为假）；空容器看「长度是否为 0」
        （[]、{}、()、set()、"" 为假；注意 [] 的值不是数字 0）
        None / False 为假是语言特殊规定
        ⚠ if x:  ≠  if x is not None:
        前者连 0 / 空串 / 空容器一起判假；后者只判「是不是 None 这个对象」
        → 业务上要区分「值为空」与「值未提供」时必须用 is None / is not None
  · is vs ==（Java 工程师高危混淆点，与 Java 正好对调）
        Python：is 比身份（是不是同一个对象，比 id()）；== 比值（调 __eq__）
        Java：== 比引用；.equals() 比值  →  两者语义正好对调
        None 是单例，判定必须用 is None（PEP8 规定），不要用 == None
  · 三元表达式：X if 条件 else Y —— 结果在前、条件在后（Java 是 条件 ? X : Y，顺序相反）
        它是表达式（有值、能直接赋值 / 塞进 print），不是语句
  · for...else：循环没被 break 才执行 else —— 是「没走 break 的收尾分支」，不是「循环结束分支」
        对比 Java：要手写 flag（boolean found=false; ...; if(!found) ...）；Python 一步到位
        用途：查找 / 质数判断（遍历完都没命中 → else 报「没找到」）
  · dict 派发替代 switch：commands.get(name) 查表 + is not None 判默认分支
        前提：函数是一等对象 —— abs 是函数对象本身，abs(-5) 才是调用
        （可存进 dict、当参数传、当返回值）
        对比 Java：Java 没有一等函数（要 interface + 匿名类 / 方法引用）
        项目关联：Day 18 的 tools/ 工具注册表就是这个模式的放大版

 ◆ Block B — 函数（5 点：⑥⑦⑧⑨⑩）
  · ⑥ def / return / 多返回值
        def 名(参数): 无括号条件、无返回类型声明；用 return 返回值
        不写 return（或只写 return）返回 None —— Python 没有 void，任何函数都有返回值
        多返回值：return a, b 本质是返回一个 tuple，调用侧解包 avg, top = stats(nums)
        无重载：同名 def 后一个覆盖前一个
        卫语句 early return：边界先 if not nums: return None, None 提前返回
        对比 Java：≈ 方法，四点差异「返回值可选、天然多返回值、无 void、无重载」
  · ⑦ 参数与默认值（可变默认参数陷阱，⭐ 今日核心验收点）
        默认值只在 def 执行时求值一次，之后每次调用复用同一个对象（存在 f.__defaults__）
        默认值若为可变对象（list / dict / set）→ 多次调用共享、互相污染
        （log_bad 第二次变 ['a', 'b']）
        规避 = 默认值用 None 占位，函数体开头 if x is None: x = []
        （不是「把默认值换成不可变类型」）
        对比 Java：Python 默认参数 ≈ static final 字段（定义时初始化一次、长期复用）；
        Java 无默认参数，靠重载
  · ⑧ *args / **kwargs
        同一个 * / ** ：定义侧收集、调用侧展开
        定义：*args → tuple；**kwargs → dict
        顺序：普通参数 → 默认参数 → *args → **kwargs
        调用：f(*seq) 展开成位置参数；f(**d) 展开成关键字参数
        对比 Java：String... ≈ *args（但 Java 收成数组）；**kwargs Java 无对应（要手传 Map）
  · ⑨ 作用域 LEGB
        查找顺序 L 局部 → E 外层 → G 全局 → B 内置
        核心规则：函数内一旦对某名字赋值，它就默认是局部名
        → counter = counter + 1 读全局会 UnboundLocalError
        改全局用 global；改外层闭包用 nonlocal
        闭包会「记住」外层变量（make_counter 累加 1 → 2）
        对比 Java：Java 方法内可读字段、靠声明区分局部/字段，无此坑；
        Python 有嵌套函数 → 多出 E 层
  · ⑩ lambda
        lambda 参数: 表达式 —— 只能一个表达式，表达式的值就是返回值
        用途：一次性回调 / 排序键 → sorted(key=lambda x: -x)、map、filter、max(key=...)
        对比 Java：≈ Java 8 lambda（x -> x*2），但 Java 可写块 {}，Python 只能一个表达式
  · 横向坑（打印型 vs 返回型函数）
        只 print、无 return 的函数返回 None；直接调用它，别再套一层 print
        （否则多打一行 None）—— 见错题 M-04-3

 ◆ Block A — 类的基础（①–⑤）
  · ① class 与实例化：`class Doc:` + `Doc()` —— **没有 new**；类是**一等对象**（可赋值 / 传参 / 存容器）
        空类体用 pass；docstring 写在类体第一行（`Doc.__doc__` 取得到）
        实例化 = 「调用类」：类名加括号即在造对象（≈ 调 __new__ + __init__）
        未挂的属性一访问 → AttributeError（Java 字段声明即存在，默认 0/null，不会报错）
  · ② self 与 __init__：__init__ 是**初始化器**，不是 Java 构造器的完整等价物
        self = 当前实例，作为**第一个形参手动声明**（Java 的 this 是隐式关键字，不用写）
        `self.x = x` 才把属性写进**实例字典** `__dict__`；漏 self. 只是局部变量 → **延迟报错**（见 M-05-4）
        默认参数用 None 占位（`metadata=None` → `if metadata is None: metadata = {}`）避开 Day4 ⑦ 可变默认值陷阱
  · ③ 实例属性 vs 类属性：类属性写在类体里（≈ Java `static`）
        查找顺序：**实例 __dict__ → 类（及 MRO）__dict__**；实例属性**遮蔽**类属性
        ⚠ `obj.attr = x` **只写实例字典**；Java `obj.staticField = x` 改的是那个 static 字段本身 ← 语义正好相反
        可变类属性被实例 append → 全类共享（与 Day4 ⑦ 同一根因）
  · ④ 三种方法：
        实例方法 `def f(self)`      —— 调用时自动塞实例；≈ Java 普通方法
        `@classmethod def f(cls)`   —— 调用时自动塞「调用方的类」；≈ Java 静态工厂（子类调用 → 返回子类实例）
        `@staticmethod def f(x)`    —— 什么都不塞；≈ Java static 方法
        装饰器是**语义开关**：删掉 @classmethod → 第一个实参落进 cls、调用直接 TypeError（见 M-05-8）
  · ⑤ 访问控制：`_x` 只是**约定**（提示「内部用」）；`__x` 在**类体内**被**名字改写**为 `_类名__x`
        `obj.__x` 在类外 → AttributeError；`obj._类名__x` 照样读得到 → **不是真私有，挡不住任何人**
        Java 对照：Java private 是编译期硬约束；Python 全靠约定 + 改写，一律可绕过
 ◆ Block B — 继承与魔术方法（⑥–⑩ 全部完成）
  · ⑥ 继承与 super()：`class Sub(Base):` —— 子类自动获得父类的类属性与方法
        `super().__init__(...)` **必须显式调**，父类属性才挂上；漏调 → 对象仍能造出来，访问父类属性时才崩
        （崩点常在**子类调用的父类方法**里，不在 __init__ 里 —— 见 M-05-4 复发）
        重写 + 叠加：子类 summary 里 `super().summary()` 先跑父类的输出，再拼子类前缀（≈ Java `super.method()`）
        子类类属性同名 → **遮蔽**父类那份，父类 `Document3.category` 不会被改（实跑：`p1.category`=pdf / `Document3.category`=kb）
        无参 `super()` 为何能省参数：编译期给类体注入隐式变量 `__class__`，
          super() 用「当前方法的第一个参数（self/cls）+ `__class__`」推出起点 → 它是**沿 MRO 往后找**，不是「找父类」
        Java 对照：Java `super` 是关键字、编译期静态绑定、只能指直接父类；Java 单继承，Python 支持多继承（⑦）
  · ⑦ 多继承与 MRO：`class C(A, B)` —— MRO 是 **C3 线性化后的一条有序线性表**（`C.__mro__` 可查）
        实跑：`C(A,B).__mro__` → (C, A, B, object) 且 `C().mark()` → 'A'；`D(B,A).__mro__` → (D, B, A, object) 且 `D().mark()` → 'B'
        方法查找：**沿 MRO 从左到右，第一个命中即停**（不再往后）
        C3 的两条保证：① 子类**永远排在父类之前**；② 同一个类**只出现一次**（菱形里 Base 只算一次 → 这正是「协作式 super()」能成立的前提）
        菱形协作链实跑：Leaf(L, R)，每层 `super().__init__()` 后 append 本类名 → `Leaf().log` → `['Base','R','L','Leaf']`（super() 逐层往后，Base 最先执行、再回卷 R/L/Leaf）
        Java 对照：Java 单继承；接口 default 方法冲突须显式 `A.super.x()`；Python 直接多继承 + 沿 MRO 隐式协作
  · ⑧ @dataclass：只写**类级注解字段**（`doc_id: str`），自动生成 `__init__` / `__repr__` / `__eq__`
        注解本身**不建属性**、运行时不校验类型（呼应 Day 1）；dataclass 靠 `__annotations__` 认字段
        `field(default_factory=dict)`：`dict` 是**工厂**（每次新建），不是值本身
        子类也要 `@dataclass`；生成 `__init__` 时**父类字段排在前面**（≈ Lombok @Data / Java 16 `record`）
        与 `record` 的关键区别：dataclass **默认可变 + 可继承加字段**、访问是**属性**；record 不可变、final、访问是**方法**
        ⚠ 类里已定义 `__repr__` 时 dataclass **不覆盖**（源码注释：Never overwrites an existing attribute）
        ⚠ 无字段注解的类套 @dataclass 是空壳：`fields()` == ()、`repr` → 'Pair()'（见 M-05-12）
  · ⑨ __repr__ / __str__：`print` / `str(x)` / `f"{x}"` → `__str__`；REPL 直接敲、`repr()`、**容器里的元素** → `__repr__`
        不重写时：`object.__repr__` → `<mod.Class object at 0x…>`；`object.__str__` **转发**到 `__repr__`
        → 所以「只写 `__repr__`」通常就够（`__str__` 会自动回退）；反之只写 `__str__` 时，容器里照样打地址
        ⚠ Java 的 `List.toString()` 用元素 `toString()`；Python 的 `list` 用元素 `repr()` ← 只写 `__str__` 必踩
        ⚠ 给父类写 `__str__` 会影响**所有子类的 print**（子类继承该 `__str__`，自己的字段被盖住）
  · ⑩ __eq__ / __len__：`==` 调 `__eq__`（默认比**身份**）；`is` 才是身份 —— 与 Java 的 `==` / `equals()` 语义**正好对调**
        ⚠ 重写 `__eq__` → Python **自动把 `__hash__` 置 None**（对象不可哈希，进不了 set / 当不了 dict key）
          → 要可哈希必须**同时**定义 `__hash__`；对照 Java「重写 equals **应**重写 hashCode」是**约定、不强制**
        实跑对照：普通类 `Pair.__hash__` → `<slot wrapper '__hash__' of 'object' objects>`（可哈希）；写完 `__eq__` 后 → `None`
        `__len__` 决定 `len(obj)`，也决定**真值**：有 `__len__` 且返回 0 → 判假（呼应 Day 4「空容器判假看长度」）
        `@dataclass` 默认 eq=True → 生成 `__eq__` 且对象**默认可哈希性被掐掉**（除非 `frozen=True`）

 【M-05-6】术语混用「可变参数」；未答默认值只求值一次的根因   #概念 #术语

 【M-05-8】@classmethod 的 cls 机制没吃透   #概念

 【M-05-9】以为 self.__class__.__name__ 能标识「方法定义在哪个类」   #概念
   现象：⑦ 项1/项2 里 A、B、C、D 四个类都写了 `def mark(self): return self.__class__.__name__`，

   根因：① `self.__class__` 返回的是**实例所属的类**，不是「定义该方法的类」——

        真跑证据：`class C2(A2,B2)`（A2.mark 用 self.__class__）实测 `C2().mark()` → `'C2'`（不是 `'A2'`）
   Java 对照：Java 的 `this.getClass()` 同样返回**运行时类**（动态类型），与「方法在哪个类声明」无关
        —— 两边一致；想拿「声明类」得用反射 `getDeclaringClass()`（Python 侧则可读 `C.mark.__qualname__`）
   复发：—（首次）；Day 6 开场自测：不看笔记回答「继承来的方法里，self.__class__ 是哪个类？」

 【M-05-10】把 dataclass 专属的 field(default_factory=...) 当成「函数参数默认值」的正解   #概念
   现象：⑧ 验收 Q3 问「换到函数参数的默认值，正确写法是什么样？」，答成
        `metadata: dict = field(default_factory=dict)` —— 那是 dataclass 的写法，不是函数参数的
   根因：把「默认值想用可变对象」的两套语境混为一谈：
        · dataclass 字段：metadata: dict = field(default_factory=dict)（field 由 dataclasses 提供、只能用在类字段上）
        · 普通函数参数：没有 field 可用，只能 None 占位 + 函数体开头重建

        （field(...) 返回的是一个 Field 对象，放进函数签名毫无意义）
   Java 对照：Java 无默认参数；两处都是「每次现场新建」的思路，但 API 不同，别串用
   复发：—

 【M-05-11】dataclasses 拦可变默认值的「时机 + 判据」说错   #概念
   现象：⑧ 验收 Q2 答「因为在 __init__ 的时候看到 dict 是可变类型」——
        ①时机说错（与同题 A1「定义这个类」自相矛盾）；②判据说错（并非通用「可变性检测」）
   根因：没看 dataclasses 的真实实现，靠直觉补机制
   正解（读 3.12 标准库 dataclasses.py 源码确认）：
        · 拦截发生在 @dataclass 装饰器处理字段时（= 类定义阶段），**不是** __init__ 运行时
        · 判据是「该默认值所属类的 __hash__ is None」（不可哈希）—— 源码注释原话：
          “Use unhashable as a proxy indicator for mutability”
          → list/dict/set 因不可哈希被拦；若自定义类型自定义了 __hash__，哪怕内容可变也不会被拦（代理判据会漏）
        · 它是 **dataclasses 库**的规定，不是 Python 语言层 —— 这点学员答对了（“不是 python 禁止的”✅）
   Java 对照：≈ Lombok 编译期对 @Data 字段做的校验；同为「库/工具」的约束，不是语言语法
   复发：—

 【M-05-12】@dataclass 误用在「无字段注解」的类上   #概念
   现象：⑩ 项1 题面要求定义「普通类 Pair」，学员写成 `@dataclass class Pair` 且手写 __init__/__eq__；
        又因一上来就写了 __eq__，没跑到题面要的「不写 __eq__ → == 为 False」那一步
   根因：没意识到 @dataclass 的字段来自**类级类型注解**（`a: int`），不是 __init__ 里的 `self.a = a`
        —— 类里没有注解就没有字段
   正解（实测）：
        · fields(Pair) == ()                  # 收集到 0 个字段
        · repr(Pair(1,2)) → 'Pair()'          # dataclass 仍生成 __repr__，但只印类名（字段为空）

          + @dataclass(eq=True) 的库规则）→ 分不清是哪套起的效
        → 想看「普通类默认行为」，必须去掉 @dataclass

 ── 💡 一、知识点速记 ─────────────────────────────────────────────
 ◆ Block A — 模块 / 包 / 导入（①②③）
  · 模块 = 一个 .py 文件；`import mod` 把**整个模块对象**绑到一个名字；`from mod import x` 只绑成员
        `from mod import *` 会污染命名空间，工程里别用
  · 模块只在**首次导入时执行一次**，之后一律从 `sys.modules`（已加载缓存）复用 → 模块级代码不重复跑
        想强制重跑要 `importlib.reload()`；这也是「模块级副作用只发生一次」的根
  · `sys.path` 决定「去哪找模块」：脚本所在目录排第一（所以 `learning/` 里的脚本能 import 同目录模块）
        找不到就 ModuleNotFoundError；改 `sys.path` 是临时手段，正规做法是装成包
  · `__name__`：**直接运行**该文件 → `"__main__"`；**被 import** → 模块名（如 `"day06_utils"`）
        → `if __name__ == "__main__":` 的代码只在直接运行时执行（≈ Java `main`，但被 import 时不跑）
  · 包 = 含 `__init__.py` 的目录（`__init__.py` 在 import 包时执行一次）；相对导入的锚点是模块自己的
        **`__package__`**，不是文件系统里的目录；脚本被直接运行时 `__name__=="__main__"`、`__package__` 空
        → `from . import x` 报 ImportError: attempted relative import with no known parent package
  · Java 对照：Python 模块 ≈ Java 一个 class 文件，但**没有 public class 名 = 文件名**的硬约束；
        包 ≈ package，可 Java 的包由 `package` 声明 + 目录结构在**编译期**定死，压根没有「相对导入」

 ◆ Block B — 依赖管理（④⑤：pyproject.toml / uv）
  · `pyproject.toml` ≈ `pom.xml`：`[project]` = 项目元数据与**运行期**依赖；
        `[dependency-groups].dev` = **开发期**依赖（mypy / ruff 这类只在本机跑的工具）
  · uv 工作流：`uv add <pkg>` / `uv add --dev <pkg>` 改 pyproject.toml + 同步环境；
        `uv sync` 按锁文件把环境拉成一致（新机器第一步）；`uv run <cmd>` 在项目环境里跑命令
        `uv.lock` = 锁文件（精确版本 + 哈希）≈ Maven 的锁定解析结果，保证「换机能复现」
  · TOML 语法 vs Python 取值是**两套语法**：`[project]` 是 TOML 表头；读进来后它只是 dict 里的
        字符串 key → 必须写 `data["project"]["name"]`（见 M-06-3）
  · Java 对照：uv ≈ Maven + nvm 合体（管版本也管依赖）；`uv.lock` ≈ dependencyManagement + 完整解析树

 ◆ Block C — ruff（lint / format）与 mypy（静态类型）
  · ruff 干两件不同的事：`ruff check` = **静态规则**（找问题）｜`ruff format` = **格式化**（改风格）
        `check` 只挑刺不改（除 `--fix` 自动修可修项）；两者分开，别混
  · Java 对照（见 M-06-5）：`ruff check` ≈ Checkstyle（风格）+ PMD/ErrorProne（F 族缺陷）；
        `ruff format` ≈ Spotless / google-java-format。Java 是四件套，ruff 一个工具全包
  · `[tool.ruff.lint] select` 的语义是**替换（覆盖）**默认集、不是叠加 → 方向要拿「默认集 vs 你写的集」
        比包含关系；本机实测 20 → 59（见 M-06-4）
  · 规则族：E/W = pycodestyle（风格，如 E501 行超长 / W293 空行带空格）；F = pyflakes（真缺陷，如
        F401 导入未用 / F823 使用前未定义）；I = isort（导入排序）
        `invalid-syntax` 来自解析层 —— 语法不合法会**整片文件**报，优先修它（呼应 Day 3 执行模型）
  · `per-file-ignores` 按 glob 关规则（`"learning/*.py" = ["E501","E402"]`）；`--statistics` 看分布
        可自动修的（W293/E741 之类）用 `--fix`；不可自动修的（如 E741 改名）要手改
  · mypy = **渐进类型（gradual typing）**：没注解的参数 / 变量 / 返回值一律当 `Any`，而 `Any`
        不与任何类型冲突 → 所以默认只在**被注解过**的地方报错（这就是「渐进」的入口）
  · mypy 是**纯静态**分析：脚本一行都不会跑（无副作用）；报错是「类型层」的事，能不能跑是「运行期」的事
        两件事可以完全相反：mypy 全红也能跑出结果，mypy 全绿也可能运行期崩
  · `[tool.mypy]` 只是**配置**（python_version / warn_unused_ignores / check_untyped_defs …），
        写配置本身**不改变检查强度**（实测条数不变）；`--strict` 才会显著变严（实测 10 → 92）
  · 常见错误码：`arg-type`（实参类型不符）/ `return-value`（返回值不符）/ `attr-defined`（属性不存在）/
        `no-redef`（同一名字重复定义）/ `call-arg`（实参个数不符）/ `call-overload`（重载/签名不匹配）/
        `operator`（对未知类型用运算符）/ `empty-body`（函数体只有 `...`）
  · Java 对照：mypy ≈ javac 的类型检查，但 Java **编译期强制**、Python 全靠外部工具；
        「注解只是提示、运行期不强制」的代价 = 类型错要等工具/mypy 才暴露，好处 = 能渐进加注解、不阻塞开发

 ◆ Block D — 异常处理（⑧⑨）
  · 四块执行顺序：try 无异常 → 跑 `else`；有异常 → 跑 `except`；`finally` **任何情况都跑**
        （哪怕 try/except 里已经 `return` —— 实测 `1 2.0 / 3 else / 4 finally` 两种输入都出现 finally）
        ⚠ `finally` 里写 `return` 会**覆盖** try/except 里已经算出的返回值
  · `raise X from e` → 设 `e.__cause__`，traceback 打两句
        "The above exception was the direct cause of the following exception"（**≈ Java `initCause()`** / 构造器传 cause）
        不用 `from` → 隐式 `__context__`，traceback 打 "During handling of the above exception, another exception occurred"
        → 读 traceback 要连这两句一起抄，否则丢掉「崩在哪个方法、谁引起的」（M-05-4 的复发点）
  · `except ... as e` 的 `e` 在**块结束时被删除**（Python 主动 `del`）→ 出了 except 块再引用它 = NameError
        目的：打断「异常对象 → traceback → 帧 → 局部变量 → 异常对象」的引用环，避免内存泄漏
        Java 对照：Java 的 catch 变量只在块内可见（作用域规则），Python 是「块结束主动删名字」
  · 裸 `except:` 抓的是 `BaseException`（含 `KeyboardInterrupt` / `SystemExit`）；`except Exception` 只抓
        `Exception` 子树。`KeyboardInterrupt` 直接继承 `BaseException`、与 `Exception` 是**兄弟** → 裸 except 会
        把 Ctrl-C 一起吞掉  ≈ Java `catch (Throwable)` vs `catch (Exception)`
  · 自定义异常层次：一个基类 `AppError(Exception)` + 按域派生子类（`ParseError(AppError)`）
        `except` 按 **isinstance 语义**匹配 → `except AppError` 既能兜住全部「预期内错误」、
        又不拦 `KeyboardInterrupt` 这类；需要差异化处理时再捕具体子类 → 粗细粒度兼顾
        Python 没有受检异常，调用方靠「基类约定 + docstring / 文档 + 测试」知道该捕哪个
  · `except` 匹配是**从上到下、第一个命中即停** → 子类要写在父类前面，否则被父类先截走
  · 捕获范围只写「预期内、且我知道怎么处理」的（见 M-06-6 / M-06-7）
  · EAFP vs LBYL：Python 偏爱 EAFP（先做、出错再捕，`try: int(s)`），Java 习惯 LBYL（先查再动）
  · Java 对照：多项 unchecked 异常都不必声明；Python 连 checked/unchecked 的区分都没有 —— 全靠约定

 【M-06-3】把 TOML 的表头写法当成 Python 的取值写法（dict key 未加引号）   #语法 #概念
   现象：④-1 写成 `data[pyproject.toml][name]` → NameError: name 'pyproject' is not defined
   根因：① Python 的取值语法里，`[]` 内是**表达式**：`pyproject.toml` 被解析成「变量 pyproject 的属性 toml」，
          `name` 被当成未定义变量 → 双双 NameError（不是「key 找不到」）
        ② 把配置文件里的 **TOML 表头** `[project]` 直接搬进 Python —— 那是 .toml 文件里的语法；
          读进来后它只是 dict 里的一个**字符串 key**，必须写 `data["project"]["name"]`
   正解：`print(f"name -> {data['project']['name']}")`
        附带预警：dependencies 是 **list**，`"..." + data[...]` 会 TypeError（str+list 不隐式转换，呼应 Day2）
   Java 对照：Java 读配置（Properties / Jackson）后取值同样用字符串 key：`cfg.get("project")`；
        「配置文件的格式语法（.properties/.toml）」与「代码里怎么取值」永远是两套语法

 【M-06-6】捕获范围开太宽，把「自造的编程错」也伪装成了「输入非法」   #概念
   现象：⑧-2 里写 `i = int(str)`（本意是参数 `text`，却把内置类型 `str` 传了进去），
        又在 parse_int 里 `except (ValueError, TypeError) as exc` —— 这个 TypeError 被一起抓走，
        于是**没有任何报错**，只抛出一句「无法把 'aas' 解析成整数」；⑧-2 的观察目标
        （traceback 的因果链）也一并被掩盖，验收时贴不出该看的那一段
   根因：`except` 只该抓「**预期内、且我知道怎么处理**」的错误；`TypeError` 在这里是
        「我自己写错的代码」的信号，混进「数据非法」的通道 = 把 bug 静默降级成业务错误
   正解：只捕该捕的 —— `except ValueError as exc: raise ParseError(...) from exc`；
        并修 `i = int(text)`
   Java 对照：≈ `catch (Exception e) { return default; }` 一刀切 —— Java 里同样反模式
   复发：—

        traceback 只贴了「后 6 行」，恰好丢掉两句 `The above exception was the direct cause of ...`

 【M-06-7】`except` 捕了一个「永远不会被抛出」的类型 → 死分支 + 异常静默穿透   #概念 #易复发
   现象：⑨-1 要求「把 parse_int 里那两处 raise 从 ValueError 改成 ParseError（保留 `from exc`）」，
        学员改了 raise，却**没同步改 except** —— 写成 `except ParseError as exc: raise ParseError(...) from exc`：
        · `int(text)` 实际抛的是 ValueError，而 `except ParseError` 接不到它（两类型无继承关系）
          → 这个 except 是**死分支**，ValueError 直接冲出 parse_int，`from exc` 也一起失效
        · 连带崩点在 `__main__`：第 95 行留着 ⑧-2 的**裸调用** `load_setting("abc")`，脚本在此就崩了，
          紧跟其后的 ⑨ `try/except AppError` 根本没跑到 → ⑨-1 期待的 `ParseError ValueError` 从未打印，
          作答区只剩 3 行空白
        · ⑧-2 造的那条 `RuntimeError: 配置项 'abc' 非法` 链也一并失效（原因同第一条）
   根因：① `except X` 只能接到 **X 及其子类**的实例 —— 类型对不上 = 永不触发；
        ② 「改了抛出的异常类型、却忘了改上层的 except」**不会报任何错**，只会静默地让异常穿透，
           属于最隐蔽的一类 bug（Java 有受检异常能让编译期兜住一部分，Python 完全没有这层保护）；
        ③ 故意报错的演示没做隔离，中断了后面本该打印的观察输出（M-05-4 导师侧提醒的复发）
   正解：
        def parse_int(text: str) -> int:
            """把字符串转成整数；失败时 raise ParseError（信息里含原始输入）。"""
            try:
                return int(text)
            except ValueError as exc:                 # ← 接住「真实抛出的那个类型」
                raise ParseError(f"无法把 {text!r} 解析成整数: {exc}") from exc
        口诀：**改异常类型 = 改契约，必须同时检查所有调用方的 except**（改一处、崩一片）
        另：`__main__` 里把 ⑧-2 的裸调用挪到**最后**，让 ⑨-1 的输出先打印
   实测（导师代改后）：`uv run python learning/day06_errors.py` → 打印 `ParseError ValueError`；
        随后第 99 行裸调用按预期崩，traceback 首行 `ParseError`、`__cause__` 为 `ValueError`
        （`ruff check` → All checks passed；`mypy` → Success）
   副作用观察（值得记住）：⑨ 之后 `load_setting` 里那句 `except ValueError` 也**变成了死分支** ——
        它接不到 ParseError，于是 ParseError 一路穿到 `__main__` 的 `except AppError` 才被抓住。
        这正是「一个 AppError 基类 + 子类」的价值：上层兜底那一处不用跟着改
   Java 对照：≈ 把 `catch (IOException e)` 留着，却把方法改成抛 IllegalArgumentException 后直冲上层 ——
        Java 里 checked 异常会强迫你处理；Python 连编译期都不看，全靠自己顺着调用链检查
   复发：—
